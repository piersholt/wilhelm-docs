# `0x4b` BMBT Tape Status

BMBT `0xf0` → Radio `0x68`

Reports cassette drive state to the radio.

### Related Commands

- `0x4a` [BMBT Tape/LED Control](4a.md)

### Example Frames

    F0 04 68 4B 05 D2       # No tape
    F0 05 68 4B 06 12 C2    # Tape inserted, side 1
    F0 05 68 4B 06 11 C1    # Tape inserted, side 2

## Parameters

One or two data bytes.

| Property | Index | Length | Type |
|:---------|:------|:-------|:-----|
| Presence | `0`   | `1`    | Map  |
| Status   | `1`   | `0-1`  | Map  |

### Presence

    NO_TAPE  = 0x05
    TAPE_IN  = 0x06

`NO_TAPE` is sent without a second byte. `TAPE_IN` may be followed by a cassette state.

### Status

    SIDE_1             = 0x12
    SIDE_2             = 0x11
    TRANSPORT_NEUTRAL  = 0x30
    FAST_REWIND        = 0x41
    FAST_FORWARD       = 0x42
    FORWARD            = 0x51
    REWIND             = 0x61

    INSERTION_STATUS   = 0x80

    DOLBY_OFF          = 0x81
    DOLBY_C            = 0x82
    DOLBY_B            = 0x84

    PLAY               = 0xE1
    STOP               = 0xE2
    ERROR              = 0xF0

The status byte is an event/state code, not a bitfield. The radio keeps separate internal state for transport/side, play/stop, Dolby mode, insertion and errors.

`TRANSPORT_NEUTRAL` clears the active forward/rewind state. The radio then uses `0x4a 0x48` to request or resynchronise the current cassette state when required.

`INSERTION_STATUS` is used during cassette insertion. The radio remembers this status and, when cassette presence later changes from `0x05` to `0x06`, sends `0x4a 0x80` back to the BMBT.

`PLAY` and `STOP` are tracked independently from the side/transport status. `PLAY` corresponds to the radio sending `0x4a 0x4b`; `STOP` corresponds to `0x4a 0x4a`.

`ERROR` latches the cassette error state in the radio and suppresses normal cassette state updates until the state machine is reset.
