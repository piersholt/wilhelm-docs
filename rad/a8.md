# `0xa8` Traffic Management Channel Response

Radio `0x68` → Navigation `0x7f`\
Radio `0x68` → GT `0x3b`

Carries RDS/TMC response records generated by the radio. The protocol is a record stream.

The navigation-side MK4 parser accepts multiple record types.\
A compact `xF` status is also used by the GT/BPF-TMC state path.

### Related Commands

- `0xa7` [Traffic Management Channel Request](a7.md)

## Record Types

| Low nibble | Common Type | Bytes | Function |
|:--|:--|--:|:--|
| `0` | `0x30` | 6 | Raw RDS/TMC group |
| `1` | `0x31` | 7 | General RDS group |
| `2` | `0x32` | 2 | Receiver/TMC status |
| `3` | `0x33` | 6 | TMC service descriptor |
| `4` | `0x34` | 2 | Receive-input mask |
| `5` | — | 5 | 32-bit compatibility/status value |
| `6` | `0x36` | 2 | 3-bit scan/source state |
| `7` | `0x37` | 2 | RDS sub-destination / receiver status |
| `F` | `0x3F` | 2 | BPF TMC state |

## `x0` Raw RDS/TMC Group

```text
x0 META C_H C_L D_H D_L
```

The analyzed BM54 emits `0x30`.

```text
META:
bit 7     stream toggle / epoch
bit 6     TIME_PATH
bit 5     META_CLASS (semantic name unknown)
bits 4..0 RDS Block B bits 4..0
```

`C_H:C_L` and `D_H:D_L` are RDS Blocks C and D.

### Time Path

When `META bit 6` is set, MK4 routes the record to `rds_time`.

When clear, it routes the five-byte group to `rds_traf_info` and the ALERT-C decoder.

### META Class

The analyzed BM54 never sets this bit. MK4 nevertheless extracts it and maps it into one of two mutually-exclusive decoded-message flags.

## `x1` General RDS Group

Seven bytes total. MK4 converts it to its `rds_group` interface rather than the TMC-specific `rds_traf_info` path.

The analyzed BM54 TMC response builder does not emit this record.

## `0x32` Receiver/TMC Status

```text
32 STATUS
```

The MK4 status decoder splits the byte into:

```text
bits 7..6
bits 5..4
bits 3..2
bit 1
bit 0
```

The BM54 uses this status in the enable/query state machine. Some individual public flag names remain unresolved.

## `0x33` TMC Service Descriptor

```text
33 SID LTN_M MGS PI_H PI_L
```

```text
SID:
bits 5..0  SID
bits 7..6  result/status flags

LTN_M:
bits 5..0  LTN
bit 6      RDS-TMC transmission mode M
bit 7      result/status flag

MGS:
bits 3..0  MGS
bits 7..4  additional status fields
```

`PI_H:PI_L` is the RDS PI code.

The core fields come directly from the RDS-TMC 3A system-information decoder.

## `0x34` Receive-Input Mask

```text
34 MODE
```

```text
TMC_TRAFFIC_GROUP = 0b0000_0001
RDS_CLOCK_TIME    = 0b0000_0010
```

The analyzed BM54 uses these bits as independent gates for:
- configured TMC traffic groups;
- RDS group 4A Clock-Time/Date.

## `x5` 32-bit Status

```text
x5 V3 V2 V1 V0
```

MK4 combines the four data bytes into one 32-bit value and accepts it in the RDS/TMC status path. The analyzed BM54 does not emit it.

Exact public semantics remain unknown.

## `0x36` Scan/Source State

```text
36 STATE
```

MK4 uses only:

```text
STATE = data & 0x07
```

The analyzed BM54 emits this from the `0x3a` scan/update path.

## `0x37` RDS Sub-Destination / Receiver Status

```text
37 STATUS
```

MK4 forwards the high nibble to `rds_sub_dest` and also decodes receiver-status subfields. The analyzed BM54 initialization path emits `37 13`.

## `xF` BPF TMC State

Two bytes. This is the compact subset also consumed by the GT BPF-TMC state path.

The examined MK4 GT recognizes high-nibble modes `1`, `2`, and `3` when the low nibble is `0xF`.

## ALERT-C Payload

For TMC raw groups (`x0`, bit 6 clear), MK4 passes:

```text
B_LOW5 C_H C_L D_H D_L
```

to `mm`.

Single-group ALERT-C fields decode as:

```text
DP        = B[2:0]
DIVERSION = C15
DIRECTION = C14
EXTENT    = C13..11
EVENT     = C10..0
LOCATION  = D15..0
```

Multi-group messages are assembled statefully and support ALERT-C optional-content labels. The examined MK4 stores a 16-entry bit-length table:

```text
0:3  1:3  2:5  3:5  4:5  5:8  6:8  7:8
8:8  9:11 A:16 B:16 C:16 D:16 E:0 F:0
```
