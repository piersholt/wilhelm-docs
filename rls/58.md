# `0x58` RLS Wiper Interval Data

RLS `0xe8` → General Module `0x00`

Carries the RLS interval value.

### Related Commands

- `0x75` [Wiper Status Request](../gm/75.md)
- `0x77` [Wiper Status](../gm/77.md)

### Example Frames

    E8 05 00 58 00 00 B5
    E8 05 00 58 FF 7F 35
    E8 06 00 58 FF 7F 00 36

## Parameters

The GM consumes the first two payload bytes as one little-endian 16-bit interval count:

    INTERVAL = byte_1 | (byte_2 << 8)

A third payload byte may be present on the bus, but the GM does not read it in this protocol form. Therefore these two frames carry the same interval value for this GM:

    FF 7F
    FF 7F 00

### Interval Handling

The GM applies the following normalization before the value enters the wiper-control state machine:

    0x0000  -> 0x0001
    other   -> unchanged

The accepted value is then doubled internally.

`0x7FFF` is treated specially during RLS initialization and acts as the no-current-interval/sentinel value in that path.

The wire count uses a 100 ms timebase. The GM doubles the received value because its internal wiper-interval arithmetic uses 50 ms units. This is confirmed by the same wiper path using the coded standstill intervals: `COD_WI_INT_STILL` selects 3 s or 5 s, represented internally by `60` or `100` timer counts respectively.

Therefore:

    physical_interval = INTERVAL * 100 ms

Examples:

    0x0001 -> 0.1 s
    0x000A -> 1.0 s
    0x0032 -> 5.0 s

`0x7FFF` remains a protocol sentinel during RLS initialization and should not be interpreted as a normal 3276.7-second interval in that state.

## Use

The value feeds the same windshield-wiper interval logic that also uses the GM wiper-stalk/potentiometer state sent back to the RLS with `0x77`.
