# `0x55` Replicate Data

The cluster will update the LCM when **any** redundant-data interval changes.

The eight data bytes have the same structure as bytes `5..12` of the LCM's `0x54` response. The VIN is not included.

Examples of the SII trip counter and time-inspection counter changing within the same mileage interval:

    # SII Trip Counter Update
    80 0B D0 55 09 83 40 40 00 00 02 74 F2    # 243,500 km, SII 0x4040, oil 0 km, 628 days
    80 0B D0 55 09 83 40 41 00 00 02 74 F3    # 243,500 km, SII 0x4041, oil 0 km, 628 days
    
    # Time Inspection Counter Update
    80 0B D0 55 09 84 40 42 00 00 02 CD 4E    # 243,600 km, SII 0x4042, oil 0 km, 717 days
    80 0B D0 55 09 84 40 42 00 00 02 CE 4D    # 243,600 km, SII 0x4042, oil 0 km, 718 days

### Properties

| Property                    | Index | Length |
|:----------------------------|:------|:-------|
| **Mileage**                 | `0`   | `2`    |
| **SII Trip Counter**        | `2`   | `2`    |
| **Last Oil Service At**     | `4`   | `2`    |
| **Time Inspection Counter** | `6`   | `2`    |

LCM treats the first two bytes as the mileage field and applies mileage validation before accepting the update. Once accepted, all eight bytes replace the corresponding bytes of the redundant-data block returned by `0x54`.
