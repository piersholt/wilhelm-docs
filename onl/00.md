# `0x00` ONL Service

ONL `0x67` → GT `0x3b`

`0x67` is a logical secondary address implemented by the GM for GATS and service traffic.

This command is used by ONL for service and GATS provisioning.\
The first data byte selects a subcommand.

### Example Frames

    67 04 3B 00 02 5A  # Select test application
    67 04 3B 00 1A 42  # Request Equipment ID
    67 04 3B 00 1B 43  # Request GATS verifier

## Parameters

Variable length.

| Subcommand | Description |
|:-----------|:------------|
| `0x00`     | Internal service trigger |
| `0x01`     | Internal service lookup |
| `0x02`     | Select test application |
| `0x03`     | Leave test application |
| `0x04`     | Parameterized internal service trigger |
| `0x05`     | CD device service operation |
| `0x11`     | 32-bit GATS key-management value |
| `0x12`     | Key blob A length |
| `0x13`     | Key blob B length |
| `0x14`     | Key blob A data |
| `0x15`     | Key blob B data |
| `0x16`     | Fixed GATS provisioning metadata |
| `0x17`     | Equipment ID |
| `0x18`     | GATS key control byte |
| `0x19`     | Reset GATS key transfer |
| `0x1a`     | Request Equipment ID |
| `0x1b`     | Request GATS verifier |
| `0x20`     | Customer text |

Subcommands `0x06`-`0x10` and `0x1c`-`0x1f` are ignored by the GT implementation documented here.

### Internal Service Controls `0x00`-`0x05`

`0x00` invokes a fixed internal service trigger without additional data.\
`0x01` performs an internal service lookup; it does not produce an I-Bus response from this command path.\
`0x04` uses the same service-trigger mechanism with one argument byte.

`0x05` performs a service operation on the active CD device, if present.\
The low-level device operation depends on the CD device implementation and is not an additional I-Bus parameter.

### Test Application `0x02` / `0x03`

`0x02` changes the boot selection from `nav` to `tst` and stores the previous selection.\
`0x03` restores the previous selection, or `nav` if no usable previous selection is available.

### GATS Key Provisioning `0x11`-`0x19`

The GT builds a 172-byte GATS key record from these subcommands.

| Offset | Size | Subcommand | Description |
|:-------|:-----|:-----------|:------------|
| `0x00` | `1`  | -          | Reserved, written as `0x00` |
| `0x01` | `1`  | `0x18`     | GATS key control byte |
| `0x02` | `2`  | -          | Reserved |
| `0x04` | `4`  | `0x11`     | 32-bit key-management value |
| `0x08` | `1`  | `0x12`     | Key blob A length |
| `0x09` | `64` | `0x14`     | Key blob A |
| `0x49` | `1`  | `0x13`     | Key blob B length |
| `0x4a` | `64` | `0x15`     | Key blob B |
| `0x8a` | `1`  | `0x17`     | Equipment ID length |
| `0x8b` | `20` | `0x17`     | Equipment ID |
| `0x9f` | `9`  | `0x16`     | Provisioning metadata |
| `0xa8` | `4`  | -          | Additive checksum |

`0x14` and `0x15` are segmented transfers.\
`0x19` clears the current transfer state.

The control and provisioning fields are opaque protocol data where the implementation does not expose a more specific standard name.

Once all required fields have been received, the GT stores the record and replies with `0x20`.

### GATS Responses

The ONL service uses three reply IDs in the opposite direction. They are documented here as responses of `0x00`, not as separate ONL command entries.

| Reply | Payload | Function |
|:------|:--------|:---------|
| `0x20` | none | GATS key transfer complete |
| `0x21` | variable | Equipment ID |
| `0x22` | 8 bytes | GATS verifier |

    3B 03 67 20 7F  # GATS key transfer complete

`0x21` returns the Equipment ID stored in the GATS key record. The observed production format is an ASCII numeric identifier.

`0x22` returns an 8-byte cryptographic verification value calculated from the stored GATS key material using an 8-byte block operation with XOR chaining.

### Equipment ID Request `0x1a`

The GT replies with `0x21` followed by the stored Equipment ID.

### GATS Verifier Request `0x1b`

The GT calculates an 8-byte cryptographic verification value from the stored GATS key material and replies with `0x22` followed by that value.

`GATS Verifier` is used here as a functional protocol name rather than as the name of a specific GATS information element.

### Customer Text `0x20`

Exactly 20 bytes following the subcommand are stored as customer text by the GT.
