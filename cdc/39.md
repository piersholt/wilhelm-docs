# `0x39` CDC Status

CDC `0x18` / `0x76` → Radio `0x68`

This command is one half of the CD changer playback control, the other being CDC Request `0x38`. It is used by the CDC changer to report its status to the radio.

The original form contains seven data bytes. Later variants extend the message with MP3 folder/track information.

### Related Commands

- `0x38` [CDC Request](38.md)
- `0x3f` [CDC ID3 Text](3f.md)

### Examples

    # CD Changer (1997), Radio: BM C23
    18 0A 68 39 02 09 00 01 00 01 09 41
    18 0A 68 39 02 09 00 21 00 07 63 0D
    18 0A 68 39 03 02 00 21 00 07 64 00
    18 0A 68 39 03 09 00 01 00 01 05 4C
    18 0A 68 39 05 09 00 01 00 01 02 4D
    18 0A 68 39 05 09 00 01 00 01 03 4C
    18 0A 68 39 05 09 00 01 00 01 04 4B
    18 0A 68 39 05 09 00 01 00 01 05 4A
    18 0A 68 39 02 09 00 3F 00 01 01 77

Later CDC variants append four additional bytes to this command. The extended form is described below.

    # CD Changer (2001), Radio: BM53
    18 0E 68 39 00 82 00 01 00 01 03 00 01 01 01 C7
    18 0E 68 39 02 89 00 01 00 01 09 00 01 01 01 C4
    18 0E 68 39 01 8C 00 01 00 01 01 00 01 01 01 CA
    18 0E 68 39 04 89 00 01 00 01 13 00 01 01 01 D8

    # CD Player 0x76, same extended format
    76 0E 68 39 00 82 00 3F 00 01 01 00 01 01 01 95

## Parameters

Normally 7 data bytes. Later CDC variants may append four additional bytes.

| Parameter     | Index | Length | Type          |
|:--------------|:------|:-------|:--------------|
| Status        | `0`   | `1`    | Map           |
| Function/Flags | `1`   | `1`    | Map / Bitfield |
| Error         | `2`   | `1`    | Bitfield      |
| Magazine      | `3`   | `1`    | Bitfield      |
| Auxiliary     | `4`   | `1`    | Opaque        |
| Disc          | `5`   | `1`    | Integer (BCD) |
| Track         | `6`   | `1`    | Integer (BCD) |

### Status
This byte reports the current CDC status.

    0x00: Stopped
    0x01: Paused
    0x02: Playing
    0x03: FFW
    0x04: RWD
    0x05: Next Track
    0x06: Previous Track
    0x07: Pending/Acknowledge
    0x08: Loading / Magazine Ready
    0x09: Magazine Checking
    0x0a: Magazine Ejected

### Function / Flags

This byte reports the current CDC playback function.

    0x02: Not playing
    0x09: Playing
    0x0c: Pause
    0x19: Scan mode
    0x29: Random mode

`0x19` and `0x29` are the playing value with the corresponding mode flag added:

    SCAN    = 0b0001_0000
    RANDOM  = 0b0010_0000

The radio tracks `SCAN` and `RANDOM` independently. The corresponding modes are controlled with `0x38`.

Later 11-byte CDC variants commonly set bit 7 (`0x80`) as well, for example `0x82`, `0x89` and `0x8c`.\
The BM54 accepts this bit but does not use it in the normal CDC playback state machine.

### Error

Bitfield. The radio treats the following bits separately:

    HIGH_TEMP  = 0b0000_0010
    CD_ERROR   = 0b0000_0100
    NO_DISC    = 0b0000_1000
    NO_DISCS   = 0b0001_0000

`CD_ERROR` reports a CD playback/read error.\
`NO_DISC` refers to the selected disc not being available.\
`NO_DISCS` is distinct from the `0x0a` magazine-ejected status.

### Magazine

This denotes which slots in the CD changer magazine are loaded with a disc.

    MAGAZINE_SLOT_1 = 0b0000_0001
    MAGAZINE_SLOT_2 = 0b0000_0010
    MAGAZINE_SLOT_3 = 0b0000_0100
    MAGAZINE_SLOT_4 = 0b0000_1000
    MAGAZINE_SLOT_5 = 0b0001_0000
    MAGAZINE_SLOT_6 = 0b0010_0000

`0x3f` therefore means all six slots are loaded.

### Auxiliary

This is an opaque CDC-side field. The BM54 copies it with the status frame but does not read or interpret it in the CDC playback state machine.

Many normal CDC implementations transmit `0x00` here.

### Disc

Integer. Binary coded decimal.

The radio converts this field from BCD using the same conversion as the track field.

    # Example: CDC Disc No. 9
    18 .. 68 39 00 09 00 00 00 09 05 ..         # Disc: 0x09
    68 .. 3b 23 cb 20 43 44 20 35 2D 30 39 ..   # "CD 9-05"

### Track

Integer. Binary coded decimal.

    # Example: CDC Track No. 12
    18 .. 68 39 02 09 00 01 00 01 12 ..         # Track 0x12
    68 .. 3b 23 c4 20 43 44 20 31 2D 31 32 ..   # "CD 1-12"
    
    # Example: CDC Track No. 16
    18 .. 68 39 00 02 00 01 00 01 16 ..         # Track 0x16
    68 .. 3b 23 c4 20 43 44 20 31 2D 31 36 ..   # "CD 1-16"

### MP3 Extended Status

Later CDC variants may append four bytes at indices `7` through `10`.\
The BM54 enables this path for the 11-byte form (`LEN = 0x0e`).

| Parameter       | Index | Length | Type    |
|:----------------|:------|:-------|:--------|
| Extended Aux.   | `7`   | `1`    | Opaque  |
| Extended Flags  | `8`   | `1`    | Bitfield |
| Folder          | `9`   | `1`    | Integer |
| Extended Track  | `10`  | `1`    | Integer |

#### Extended Flags

    FOLDER_TRACK = 0b0000_0001

When `FOLDER_TRACK` is set, the radio uses the extended folder and track fields and enables the associated ID3/metadata path.

#### Folder / Extended Track

Both values are plain binary integers, not BCD. They form the MP3 folder/track pair shown by compatible radios.

    18 0E 68 39 02 89 00 01 00 01 09 00 01 01 01 C4
                                             ^^ ^^
                                         Folder Track

The extended track value replaces the normal BCD `Track` field while this mode is active.\
The normal `Disc` field remains unchanged.

When either the folder or extended track changes while playing, the radio clears its cached ID3 text and requests fresh metadata using `0x3f`.

Index `7` is copied as part of the extended status and participates in the radio's whole-frame change detection.\
A change to this byte therefore causes a CDC status update even when the other fields stay unchanged.

The BM54 does not interpret the value itself: it is not masked, compared with defined values, stored as a dedicated CDC state, displayed, or used by the playback/ID3 logic. All extended OEM examples above carry `0x00`. It is therefore documented as an opaque extended-status field rather than assigning a speculative producer-side meaning.
