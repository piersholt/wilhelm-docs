# `0x3f` CDC ID3 Text

Radio `0x68` ↔ CDC `0x18` / `0x76`

Requests and transfers ID3 metadata for the extended CDC/MP3 mode.

### Related Commands

- `0x38` [CDC Request](38.md)
- `0x39` [CDC Status](39.md)

### Example Frames

    68 04 18 3F 8E C5   # Request ID3 text

CDC replies use the same command byte with a text selector followed by the text data.

    18 .. 68 3F 02 <text> ..
    18 .. 68 3F 04 <text> ..
    18 .. 68 3F 08 <text> ..

## Request

The radio requests a metadata refresh with one data byte:

    0x8e: Request ID3 text

The request is sent after the current extended folder/track identity changes while ID3 display is enabled.

## Text Response

Variable length. The first data byte selects the metadata field; the remaining bytes contain its text.

| Property | Index | Length | Type    |
|:---------|:------|:-------|:--------|
| Type     | `0`   | `1`    | Map     |
| Text     | `1`   | `-1`   | String  |

The radio uses the low nibble of `Type` and accepts up to 30 text bytes for each field.

| Type | Display Row | Common Content |
|:-----|:------------|:---------------|
| `0x02` | `1` | Title |
| `0x04` | `2` | Album |
| `0x08` | `3` | Artist |

The radio itself treats these as three separate ID3 text fields. 

The high nibble of `Type` is not used by the analyzed BM54 receive path.\
Other low-nibble values do not update the three ID3 fields.

## Use Cases

ID3 display is enabled or disabled with `0x38 0x0c`. The CDC advertises the extended folder/track path through the extended `0x39` status.

When the folder or track changes, the radio clears the previous three text fields, sends `0x3f 0x8e`, and updates the display as the CDC returns the three text fields.
