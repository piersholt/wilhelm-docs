# `0x83` IHKA A/C Control

IHKA `0x5b` → IKE `0x80`

Carries the air-conditioning compressor request and the associated compressor-load and auxiliary-fan request information to the instrument cluster.

### Example Frames

    5B 05 80 83 00 00 5D
    5B 05 80 83 80 08 D5
    5B 05 80 83 D1 40 CC
    5B 05 80 83 D8 A0 25

### Related Commands

- `0x82` [IHKA Status](82.md)

## Parameters

Fixed length. Two data bytes.

| Parameter   | Index | Length | Type     |
|:------------|:------|:-------|:---------|
| **Control** | `0`   | `1`    | Bitfield |
| **Request** | `1`   | `1`    | Integer  |

### Control

    AC_REQUEST = 0b1000_0000

#### A/C Request `0b1000_0000`

Requests air-conditioning compressor activation.

The remaining control bits and the second byte carry compressor-load and requested auxiliary-fan information. The exact layout is not confirmed yet.

## Payload Variants

The parameter description above applies to the two-byte payload used by earlier IHKA variants.

Later IHKA variants can use an extended four-byte payload. The E83 LCI IHKA (`IHK_E83.C18`) uses this extended format.

### Extended Frame

    5B 07 80 83 P0 P1 P2 P3 CS

### Extended Parameters

Fixed length. Four data bytes.

| Parameter             | Index | Length | Type     |
|:----------------------|:------|:-------|:---------|
| **Control**           | `0`   | `1`    | Bitfield |
| **Auxiliary Request** | `1`   | `1`    | Bitfield |
| **Reserved**          | `2`   | `1`    | Integer  |
| **EWP Request**       | `3`   | `1`    | Bitfield |

### Extended Control

    TQ_ACCIN     = 0b0001_1111
    LV_REQ_TCO_L = 0b0010_0000
    LV_ACCIN     = 0b0100_0000
    LV_ACIN      = 0b1000_0000

#### A/C Compressor Torque `0b0001_1111`

Requested A/C compressor load torque.

    TQ_ACCIN_MIN = 0x00   # 0 Nm
    ...
    TQ_ACCIN_MAX = 0x1F   # 31 Nm

The compressor coding (`GEREGELTER_KOMPRESSOR`, small/large) affects the compressor regulation and the calculated torque request.

#### Lower Coolant Temperature Request `0b0010_0000`

Requests a lower engine coolant temperature.

    LV_REQ_TCO_L_INACTIVE = 0b0000_0000
    LV_REQ_TCO_L_ACTIVE   = 0b0010_0000

#### A/C Compressor Request `0b0100_0000`

Qualified A/C compressor activation request (`LV_ACCIN`).

The IHKA sets this bit when the general A/C request is active and the compressor regulation requests compressor operation after its enable and inhibit conditions have been evaluated.

    LV_ACCIN_OFF = 0b0000_0000
    LV_ACCIN_ON  = 0b0100_0000

It is not generated without `LV_ACIN`.

#### A/C Request `0b1000_0000`

General A/C / engine-load request (`LV_ACIN`).

    LV_ACIN_INACTIVE = 0b0000_0000
    LV_ACIN_ACTIVE   = 0b1000_0000

In `IHK_E83.C18`, this request can be generated by:

- the normal A/C request
- `LDA_BEI_VERBRAUCHER`, when coded active
- `LDA_BEI_UNTERSPANNUNG`, when coded active


### Auxiliary Request

    LV_REQ_HEAT    = 0b0000_0001
    HEAT_POWER_REQ = 0b0000_0010
    RESERVED       = 0b0000_0100
    ALIVE          = 0b0000_1000
    N_ECF          = 0b1111_0000

#### Increased Heat Request `0b0000_0001`

Heating request corresponding to `LV_REQ_HEAT`.

    LV_REQ_HEAT_INACTIVE = 0b0000_0000
    LV_REQ_HEAT_ACTIVE   = 0b0000_0001

#### Heating Power Request `0b0000_0010` (TBC)

Second heating-related engine request.

In `IHK_E83.C18`, the same bit is used by both `EL_DURCHLAUFERHITZER` and `ANFORDERUNG_HEIZLEISTUNG`; its exact meaning is still to be confirmed.

    HEAT_POWER_REQ_INACTIVE = 0b0000_0000
    HEAT_POWER_REQ_ACTIVE   = 0b0000_0010

#### Reserved `0b0000_0100`

Always zero in the examined `IHK_E83.C18` firmware.

#### Alive `0b0000_1000`

Alive/toggle bit. The firmware alternates this bit when preparing successive `0x83` updates.

#### Auxiliary Fan Level `0b1111_0000`

Requested electric auxiliary-fan level.

    N_ECF_MIN = 0b0000
    ...
    N_ECF_MAX = 0b1111

The fan level is stored in the upper nibble.

    N_ECF = (P1 >> 4) & 0x0F

### Reserved

The E83 LCI IHKA firmware examined sets this byte to `0x00`.

    P2 = 0x00

No other use has been identified for this byte in `IHK_E83.C18`.

### EWP Request

Request for the electric engine coolant pump when `ELEKTR_MOTORWASSERPUMPE` is coded active.

The upper nibble contains a quantized request level from 0 through 14. The lower nibble is fixed to `0x7`.

    EWP_LEVEL_0  = 0x07
    EWP_LEVEL_1  = 0x17
    EWP_LEVEL_2  = 0x27
    EWP_LEVEL_3  = 0x37
    EWP_LEVEL_4  = 0x47
    EWP_LEVEL_5  = 0x57
    EWP_LEVEL_6  = 0x67
    EWP_LEVEL_7  = 0x77
    EWP_LEVEL_8  = 0x87
    EWP_LEVEL_9  = 0x97
    EWP_LEVEL_10 = 0xA7
    EWP_LEVEL_11 = 0xB7
    EWP_LEVEL_12 = 0xC7
    EWP_LEVEL_13 = 0xD7
    EWP_LEVEL_14 = 0xE7

    EWP_NOT_APPLICABLE = 0xF7

`0xF7` is the value used when the electric engine coolant pump is not enabled and must not be interpreted as request level 15.

The active request level can be decoded as:

    EWP_LEVEL = (P3 >> 4) & 0x0F

This value is a coolant-pump request, not a measured pump speed.
